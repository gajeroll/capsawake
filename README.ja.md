# CapsAwake

[English](README.md)

[![CI](https://github.com/gajeroll/capsawake/actions/workflows/ci.yml/badge.svg)](https://github.com/gajeroll/capsawake/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

CapsAwake は、Mac の **Caps Lock** キーをスリープ防止の物理スイッチにするメニューバーアプリです。Caps Lock がオンのときはシステムスリープが無効化され、MacBook のディスプレイ（蓋）を閉じた状態でもローカル処理を継続できます。Caps Lock をオフにすると通常のスリープ動作に戻ります。

[Capsomnia](https://github.com/fuji-mak/Capsomnia) に着想を得た独立した再実装であり、異なるアーキテクチャ（明示的なステートマシン、XPC デーモン、sudoers 不要）を採用しています。

CapsAwake はテレメトリの収集、ネットワーク通信、アカウント登録を一切行いません。インターフェースは英語と日本語に対応し、設定で固定しない限りシステム言語に追従します。

外部ディスプレイを接続せずにクラムシェル状態（蓋を閉じた状態）で Mac のスリープを防ぐ公的 API は `pmset -a disablesleep` のみであるため、root 権限で動作するバックグラウンドデーモンをインストールします。デーモンが実行する処理、通信対象、書き込むファイルなどの詳細は [SECURITY.md](SECURITY.md) に明記されています。

![CapsAwake menu](docs/menu.png)

## 動作要件

- macOS 14 以降
- Apple Silicon（Universal バイナリおよび Intel Mac は非対応）
- 初回インストール時の特権バックグラウンドデーモン登録に対する管理者承認

## インストール

1. [GitHub Releases](https://github.com/gajeroll/capsawake/releases) から公証済み ZIP アーカイブ（公開後は `CapsAwake-1.0.0.zip`）をダウンロードします。
2. アーカイブを展開し、`CapsAwake.app` を `/Applications` に移動します。
3. `CapsAwake.app` を起動します。初回起動時に **システム設定 → 一般 → ログイン項目と拡張機能** でバックグラウンドデーモンを承認します。

> 注: 現在 Homebrew によるインストールには対応していません。

## ソースコードからのビルド

```sh
git clone https://github.com/gajeroll/capsawake.git
cd capsawake
make build
make test
SKIP_SIGNING=true ./scripts/build-app.sh ~/Applications/CapsAwake.app
open ~/Applications/CapsAwake.app
```

ソースビルドには macOS 14 以降および Swift 6.2（Xcode 26）が必要です。ローカライズをコンパイルする `xcstringstool` は Command Line Tools ではなく Xcode に同梱されています。

> **ソースビルドでは実際のスリープ防止は動作しません。** スリープ無効化はデーモンの役割であり、launchd はサービス登録時に記録された起動制約（Developer ID で公証されたバイナリ）を強制します。アプリ UI やキー監視は動作しますが、スリープ設定の変更は失敗します。スリープ防止自体を検証するには `make notarize` によるビルドまたは公式の [リリース版](https://github.com/gajeroll/capsawake/releases) が必要です。詳細は [CONTRIBUTING.md](CONTRIBUTING.md#trying-out-sleep-prevention) を参照してください。

アドホック署名（`SKIP_SIGNING=true`）はアプリの識別情報をコードハッシュに固定するため、リビルドのたびに macOS のアクセシビリティ許可が解除されます。キーチェーンアクセスの `Apple Development` 識別子または自己署名の `CapsAwake Dev` 証明書で署名すると、バンドル識別子と証明書に紐づけられ、リビルド後も許可が維持されます。

```sh
SKIP_SIGNING=true SIGNING_IDENTITY="Apple Development" ./scripts/build-app.sh ~/Applications/CapsAwake.app
```

### コード署名と Team ID

公式リリースは Apple Team ID `H9DPAP9M7B`（`AppIdentity.teamIdentifier`）で署名されています。ただし、実行中のアプリおよびデーモンはこの定数を盲信しません。自身に付与されたコード署名内の Team ID から動的に XPC コード署名要件を生成します（`Sources/CapsAwakeSystem/SelfSigningTeam.swift` の `SelfSigningTeam`）。

別の Apple Development または Developer ID 証明書で署名されたフォークも、ソースコードを改変することなくそのまま動作します。アドホック署名（`SKIP_SIGNING=true` または ID `-`）には Team ID が含まれないためフェイルクローズとなり、デーモンは全クライアントを拒絶し、アプリもデーモン接続を拒絶して統合ログにエラーを出力します。`#if DEBUG` による回避策はありません。

## 権限

| 権限 | 必要な場面 | 理由 |
|---|---|---|
| バックグラウンドデーモン (root) | スリープ制御の常時 | ユーザーに代わって `pmset disablesleep` を適用 |
| アクセシビリティ | Caps Lock を CapsAwake 専用にする場合のみ | キーイベントから Caps Lock を除去するローカルイベントフィルタを適用（ログ記録や外部送信は一切行いません） |

デーモンはアプリアプリバンドル内の `CapsAwakeDaemon` として動作し、`SMAppService` で登録されます。最後のクライアントが切断されると、短時間の猶予期間ののち前回の `SleepDisabled` 値を復元します。起動時の整合性チェックでも、2分以内にクライアントが再接続しなければ同様に復元します。

アプリバンドルを削除しただけでは完全なアンインストールにはなりません。デーモン登録の記録が Background Task Management に残り、ログイン項目と拡張機能に表示され続けます。[`scripts/uninstall.sh`](scripts/uninstall.sh) を実行すると、アプリを安全に終了して設定を戻し、デーモン登録を解除し、`/Library/Application Support/CapsAwake/` 下の root 保持状態を削除します。

起動時、CapsAwake はまず Caps Lock LED の状態を確認し、点灯していればスイッチがオンであるとみなします。その後 `SleepDisabled` を確認し、クラッシュ等で残った不正な `true` 状態をクリアします。

デーモン登録の承認は、**システム設定 → 一般 → ログイン項目と拡張機能** で一度行う必要があります。承認されるまではスリープ設定を変更できません。メニューバーアイコンに警告が表示され、メニューに **ログイン項目の設定を開く…** が提示されます。CapsAwake は数秒ごとに自動確認するため、設定で承認するだけで反映されます。

macOS のアクセシビリティ権限は外部で付与されます。CapsAwake は起動時に一度プロンプトを表示した後は付与されるまでポーリングするため、許可後のアプリ再起動は不要です。権限が不足している間はメニューバーアイコンに警告が表示され、**アクセシビリティ設定を開く…** が提示されます（アイコン非表示時は通知が送られます）。

Caps Lock の切り替え自体はハードウェアのロック状態を直接読み取るため、権限なしで動作します。アクセシビリティが必要となるのは Caps Lock キーを完全に CapsAwake 専用に割り当てる場合のみです。権限がない状態でこの設定を行おうとするとフェイルクローズとなり、大文字が入力され続けるのを防ぐためスリープ防止を拒否します。

## エネルギーモード

スリープ防止がオンの間、CapsAwake は Mac のエネルギーモードを切り替え、オフ時、アプリ終了時、またはクラッシュ時に元の設定を復元します。デフォルトは **低電力** です。

macOS はエネルギーモードを電源ソース（バッテリー / 電源アダプタ）ごとに管理します。設定で個別に分けない限り、CapsAwake では同一の設定が適用され、各ソースの元の値は個別に記録されて保護されます。「自動」モードのほか、対応端末では「高出力」も選択可能ですが、発熱と電力消費が増加するため **非推奨** として扱われます。エネルギーモードに対応していない Mac ではこの項目は表示されません。

この機能全体は **設定 → エネルギーモード** で無効化できます。

## インターフェース

UI 全体は SwiftUI の `MenuBarExtra` および標準の設定ウィンドウ（⌘,）で構成されています。

設定ウィンドウには使用頻度順に項目が並んでいます: CapsAwake、Caps Lock、ディスプレイとカバー、スリープ防止の維持、エネルギーモード、一般、権限、詳細。メインスイッチには ⇪ のショートカットヒントが表示されます。メニューバーのメニューには即座に必要な操作（スイッチ、**設定…**、**CapsAwake を再起動**、**終了**）と、対応が必要な場合の警告行のみが表示されます。両方の UI は同じ状態ストアを参照します。

権限が不足している場合のみ、設定ウィンドウの最上部に **対応が必要です** ブロックが表示され、直接解決ボタンが提示されます。通常の権限セクションは常に下部の固定位置に配置され、権限の付与状況に関わらずシステム設定への導線を提供します。

スイッチ類は設定値ではなく現在のキーボード状態をリアルタイムに反映します。**大文字入力に固定** は、マウス操作やショートカットキーで大文字入力モードを直接切り替えます。

Caps Lock 本体の動作は **設定 → Caps Lock** で設定します:
- **Caps Lock を CapsAwake 専用にする**: Caps Lock のキーイベントを捕捉し、大文字入力を独立して制御できるようにします（アクセシビリティ権限が必要）。
- この設定をオフにすると通常の Caps Lock として動作し、1 回の押下で大文字入力とスリープ防止が同時に切り替わります。この場合、**大文字入力に固定** スイッチは表示されません。

## 1 つのキーに 2 つのスイッチ

Caps Lock を CapsAwake 専用にした場合、Caps Lock 単体でスリープ防止を切り替え、**⇧⇪**（Shift+Caps Lock）で従来の大文字入力を切り替えます。両者は独立しており、組み合わせ入力がスリープ防止に影響することはなく、Caps Lock 単体入力が大文字状態を変更することもありません。

組み合わせる修飾キーは **設定 → Caps Lock** で自由に設定できます（⌃、⌥、⇧、⌘ と Caps Lock の組み合わせ）。キーの記録はアクセシビリティ権限なしで動作します。

曖昧な動作を防ぐため、修飾キーの組み合わせは完全に一致する必要があります。組み合わせを解除すると Caps Lock は常に CapsAwake のスイッチとなり、大文字入力は設定またはメニューバーから切り替えます。

キーボードの LED はスリープ防止の状態のみを示します。大文字入力はイベントフィルタによってキーイベントに Caps Lock 修飾フラグを付与することで実現され、ハードウェア LED はスリープ防止の状態に従って維持されます。

ハードウェアロックが点灯していても、フィルタによって通常の大文字入力が抑止されます。フィルタが届かない環境（ロック画面、ユーザー簡易切り替え、安全なパスワード入力欄など）では、CapsAwake はハードウェアロックを一時的に消灯し、セッション復帰時に再点灯します。スリープ防止処理自体はその間も継続します。

Shift を押したときに小文字を入力する Windows 風の動作を好む場合は、**設定 → Caps Lock → Shift キーで小文字を入力** を有効にします。イベントフィルタがキーイベントの文字を直接小文字に変換しつつ、IME やショートカット用の修飾キーはそのまま保持します。

メニューバーアイコンは両方のスイッチ状態を独立して表示します:
- 緑のアウトライン: スリープ防止中、大文字オフ
- 塗りつぶしアイコン: 大文字オン、スリープ防止オフ
- 緑の塗りつぶしアイコン: 両方オン
- アウトラインアイコン: 両方オフ

## キー押下時の遅延（CapsLockDelay）

macOS はキーボードの `CapsLockDelay`（標準で約 75 ms）より短い Caps Lock の押下を無視します。CapsAwake は起動時にこの遅延をゼロに上書きして素早いタップを取りこぼさないようにし、終了時に元の値を復元します。この設定は **設定 → Caps Lock** で変更できます。

メニューバーアイコンを非表示にした状態で Finder から再度 CapsAwake を開くと、設定ウィンドウが表示されます。

## カバーを閉じた動作とクラムシェルモード

macOS の標準クラムシェルモードは、カバー（蓋）が閉じられ、**かつ** 外部ディスプレイと電源が接続されている場合に動作します。

CapsAwake は外部ディスプレイがなくてもカバーを閉じた状態でのスリープを防止します。外部ディスプレイがない状態でカバーが閉じられた場合は、CapsAwake 自体がディスプレイのスリープを要求して画面を消灯しつつ処理を続行します。外部ディスプレイが接続されている場合は通常のクラムシェル動作を維持します。

他のアプリが表示スリープアサーションを保持している場合はバックオフを伴って再試行し、可能な場合はブロックしているプロセス名を通知します。

## 安全機能

- 重大な熱状態、カバーを閉じた状態での深刻な熱状態、または **設定 → スリープ防止の維持** で指定したバッテリー残量（デフォルト: 5%）に達した場合、自動的にスリープ防止を解除します。
- スリープタイマー連動（オプション）: ディスプレイが消灯しており、システム本来のスリープタイマー時間が経過した場合にスリープを許可します。
- スリープ防止中は 5 秒ごとに `IOPMrootDomain` の `SleepDisabled` を検証し、外部から書き換えられた場合は再適用します。
- 変更前の `SleepDisabled` およびエネルギーモードの値を `/Library/Application Support/CapsAwake/baseline.plist` に記録し、デーモンの再起動やクラッシュ後も確実に元の状態を復元します。
- 複数のスリープ防止ツールを同時に使用しないでください。

## トラブルシューティング

- **デーモンの承認**: スリープ防止が有効にならない場合は、**システム設定 → 一般 → ログイン項目と拡張機能** で `CapsAwakeDaemon` が有効になっているか確認してください。
- **アドホックビルドでのアクセシビリティ権限のリセット**: アドホック署名されたバイナリをリビルドすると macOS のアクセシビリティ権限が無効化されます。`Apple Development` 証明書で署名するか、**システム設定 → プライバシーとセキュリティ → アクセシビリティ** で再度許可してください。
- **Gatekeeper 初回起動時の警告**: ダウンロードしたバイナリの初回起動時に警告が表示される場合は、Finder で `CapsAwake.app` を右クリック（または Control を押しながらクリック）して **開く** を選択してください。
- **アドホック署名と root デーモン**: アドホック署名（`SKIP_SIGNING=true`）のバイナリは launchd および XPC のコード署名制約により root デーモンと通信できません。スリープ防止の動作確認には開発者証明書での署名または公証済みリリースを使用してください。
